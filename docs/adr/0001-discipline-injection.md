# ADR 0001：主 agent 纪律的「快照 + 日志」注入

- **状态**：已接受
- **日期**：2026-09-12
- **背景**：主 agent（用户直接对话的 pi 会话）在工作流活跃期间必须遵守纪律（秘书不是施工队、决策走协议、结束即失效），但早期做法是把这段文本手抄进每个项目的 `CLAUDE.md`：不可迁移、会漂移、只在项目内生效，而且"结束即失效"只能靠模型自觉。

## 决策

1. **内容与路由分离**。纪律文本（提示词）与"何时注入"（代码）分开：前者的单一来源是 `discipline.md`（内容 hash 前 8 位作为版本号），后者是 `discipline-router.mjs` 里的纯函数，模型不参与任何路由决策。
2. **只在不产生额外缓存代价的时刻写 system prompt 基线**（checkpoint）：
   - `session_start`（会话开始/恢复/分叉，缓存为空）；
   - `session_compact`（压缩本来就会重建上下文）；
   - `session_tree`（分支切换重建上下文）。
3. **其余状态变化只做尾部追加**（append）：激活 / 挂起 / 解除各追加一条通知，永不删除、永不清旧加新——从前面改变文本会让缓存从头失效，从尾部追加只增加新 token。
4. **陈旧性不对称且安全**：基线最多停留在"偏保守"的一侧（说活跃但已结束），且措辞规定"最新通知优先"；危险方向（说无纪律但实际活跃）不会发生，因为激活永远走尾部追加完整纪律文本。
5. **运行中途压缩的补写**：pi 的自动压缩可以发生在一次 agent run 的工具调用之间，此时不会再触发 `before_agent_start`。由 `before_provider_request` 检查 system 段是否带有纪律标记，缺失时补写；绝不逐轮开关。
6. **关键红线机械执行**：纪律生效期间，`tool_call` 钩子直接拒绝主 agent 的 `edit` / `write`。子 agent 以 `--no-extensions` 启动，不受影响。
7. **逃离机制**：
   - 自动逃离：工作流 pass / 终止后，尾部追加"解除"通知，下一次 checkpoint 清空基线；
   - 强制逃离：`/dev-review escape --note "原因" [--minutes N | --forever]`（限时挂起，默认 30 分钟；`--forever` 需显式声明）、`escape off`、`escape status`；挂起/恢复写入项目本地 `.ai-dev-review/discipline-audit.jsonl`；
   - 挂起期间若改动工作流范围内文件，纪律要求在日志或决策 note 中注明「未经工作流评审」。

## 备选方案与取舍

| 方案 | 缓存代价 | 权威性 | 残留 | 结论 |
| --- | --- | --- | --- | --- |
| 纪律常驻 system prompt | 0 | 最高 | 常驻上下文；无法机械自动逃离 | 备选（更省缓存，但不清爽） |
| 每次状态翻转改 system prompt | 每生命周期 1 次全量重算 | 高 | 无 | 未采纳（本方案可做到 0 次） |
| 每轮尾部追加 + 清旧副本 | 每轮从清理点起失效 | 高 | 无 | 未采纳（每轮开销） |
| **本方案（快照 + 日志）** | **0 次额外失效** | 检查点后 system 级，期间消息级（有硬拦截兜底） | 少量通知文本留到下次压缩 | 采纳 |

## 后果

- 工作流全生命周期零额外缓存失效（可用 pi 的 `showCacheMissNotices` 实测）。
- 实现复杂度略增：路由需要去重键（`appendedKey`）、override 状态与审计日志。
- 陈旧窗口只可能偏保守；退出条件从"模型自觉"变成机械事实。

## 验证

- `discipline-router.test.mjs` / `discipline-runtime.test.mjs`（15 用例）覆盖：激活/解除/挂起/过期/去重/硬门/项目根查找。
- 端到端冒烟（假 pi + 临时项目夹具）：blocked 注入基线 → edit 拦截 → escape 放行 → 恢复拦截 → pass 解除 → 压缩清空 → 无工作流零注入。
